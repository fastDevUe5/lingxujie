# 实战诊断 003：Boss 模型散开 —— 逆绑定矩阵转置了两次

> **症状：`MX_BOSSCOWF` / `MX_BOSS001` 在视口里是**散落在地的身体部件**，不是站立的角色。**
>
> **结论：导出器把**已经是列主序**的逆绑定矩阵**又转置了一次**，
> 平移量从 glTF 期望的 12/13/14 槽跑到了 3/7/11 槽。
> glTF 读到的是全零 → 每根骨骼的绑定姿态被声称在原点 → 蒙皮把网格打散。**
>
> **这是本系列第一次做到「一行代码的缺陷 + 可证伪的机制」。**
>
> **日期：2026-11-26 · UE 5.8.4 · 反编译源码 + glTF 二进制实测**

---

## 一、起点：一句记录，而且是**错的**

**既有记录：「对比：`MX_BOSS001_STATIC`（用旧方式导的静态网格）仍然散开。」**

**第一步就推翻了它（✅ 实测 bounds）：**
```
MX_BOSSCOWF        bounds extent (924.5, 512.7, 550.7) cm   ← 9.2 × 5.1 × 5.5 米，这才是散开的
MX_BOSS001_STATIC  bounds extent ( 96.2, 217.1,  76.1) cm   ← 正常尺寸
MX_BOSS001         bounds extent (149.9, 194.2, 132.7) cm   ← 正常尺寸
```

**→ 散开的是 `MX_BOSSCOWF`，不是记录里写的 `MX_BOSS001_STATIC`。**

**⚠️ 这是第三次「既有记录不可信」。本系列的经验是：**记录里的每个判断都要重新验。****

---

## 二、第二步：截图，看见问题

**`Saved/shot_scatter2.png` —— 画面中央能看到散落的身体部件：棕色大块、红蓝躯干、零碎小块。**

**→ 不是「模型小」，是「模型散」。**

## 三、第三步：量长轴 —— 得到一个假的线索

**✅ 实测（`diag_scatter_step2.py`）：**

**三个模型 **Z 都是最小的** —— 看起来像「躺平了」。**

**⚠️ 但这是个**假线索**。接下来的测量把它否掉了。**

### 3.1 为什么不能靠尺寸判断朝向

**源空间实测（`diag_scatter_step3.py`）：**
```
boss001  源空间: X=296.9  Y=272.2  Z=207.7
bird 108 源空间: X=150.3  Y=111.0  Z=136.3   ← Z 最长
```

**`boss001` 源空间 X 最长 —— 一个 Boss 横着比竖着宽，可能是有尾巴/翅膀。
**`bird` 源空间 Z 最长 —— 站着。**

**→ 尺寸给不出确定答案。一个宽扁的生物和一个躺下的生物，包围盒长得一样。**

## 四、第四步：骨骼给出**决定性的、完全意外的线索**

**`get_bone_transform` 在绑定姿态下读每根骨骼的世界坐标（✅ 实测）：**
```
=== MX_BOSS001: 67 bones ===
  Bip01          idx=0   world=(9350.0, -6200.0, 3740.0)
  Bip01-Head     idx=7   world=(9350.0, -6200.0, 3740.0)
  Bip01-L-Hand   idx=13  world=(9350.0, -6200.0, 3740.0)
  ...
  bone span X: 0.0 cm
  bone span Y: 0.0 cm
  bone span Z: 0.0 cm
```

**🔴 **全部 67 根骨骼都在同一个点** —— 就是 actor 的位置，跨度为零。**

**→ 骨架是**退化的**。这才是「散开」的真机制，不是朝向问题。**

---

## 五、第五步：查 glTF，定位到矩阵

**关节节点的平移是对的（✅ 实测）：**
```
skin 0 joints: 67
  joints with zero translation: 0
  joints with non-zero translation: 67
  largest translation component: 1.332

    Bip01        translation = [-0.00145, -3.49e-10, -1.3319]   ← 根在 z=-1.33m
    Bip01 Spine  translation = [0.1434, -0.00013, -1.36e-05]
    Bip01 Head   translation = [0.1044, 1.13e-08, -2.06e-08]
```

**但逆绑定矩阵不对（✅ 实测）：**
```
inverseBindMatrices accessor: count=67, type=MAT4
  IBM 平移为零:      67    ← 全部
  IBM 平移非零:       0
```

**glTF 的蒙皮公式：**
```
jointMatrix[i] = inverse(meshWorld) × globalTransform(joint[i]) × inverseBindMatrix[i]
```

**→ IBM 声称「每根骨骼的绑定姿态在原点上」。
**→ 公式里的 `globalTransform × IBM` 不再抵消绑定位置。
**→ 每个顶点被错的矩阵变换 → **散开**。**

## 六、第六步：直接验假设 —— 平移跑到哪去了

**假说：`invert()` 返回的列表**已经是列主序**（平移在 12/13/14），
`build()` 又按「行主序转列主序」转置了一次，把平移推到 3/7/11。**

**✅ 实测（`diag_scatter_step6.py`）：**
```
idx  slot3      slot7      slot11     | slot12     slot13     slot14
0    32.1517    -129.2512  0.1452     | 0.0000     0.0000     0.0000
1    0.1452     -0.5084    0.0000     | 0.0000     0.0000     0.0000
2    -129.2512  0.1450     32.1517     | 0.0000     0.0000     0.0000
3    -143.5671  3.4216     32.0969     | 0.0000     0.0000     0.0000
...

matrices with translation in slots 3/7/11:   67
matrices with translation in slots 12/13/14:  0

VERDICT: the translation is in the wrong slots - the matrix was transposed twice
```

**→ **假设成立，67/67 全中。****

## 七、根因（`Tools/export_mod_anim_gltf.py`）

```python
# 第 683-697 行 invert() 的返回值 —— 平移已经在 12/13/14，即已经是列主序
return [
    r[0], r[1], r[2], 0.0,
    r[3], r[4], r[5], 0.0,
    r[6], r[7], r[8], 0.0,
    -(tx * r[0] + ty * r[3] + tz * r[6]),      # ← 12
    -(tx * r[1] + ty * r[4] + tz * r[7]),      # ← 13
    -(tx * r[2] + ty * r[5] + tz * r[8]),      # ← 14
    1.0,
]
```

```python
# 第 733-738 行 build() —— 又转置了一次
world = bind_world(bone)
inverse = invert(world)
# Transpose into glTF's column-major order.        ← 注释说的事已经做完了
column_major = [inverse[c * 4 + r] for r in range(4) for c in range(4)]
```

**→ 注释说「转置成 glTF 的列主序」，但**`invert()` 返回的已经是列主序**。
**→ 转置把平移从 12/13/14 挪到 3/7/11，而 glTF 读 12/13/14，拿到零。**

### 7.1 修复（**未应用**）

```python
# inverse 已经是列主序，直接用
column_major = inverse
```

**一行改动。**

## 八、🔴 为什么这个 bug 之前没被发现

**因为我做的是**自证**的验证：**

**之前记录的验收方式是「`IBM = inverse(bindWorld)`，往返误差 2.22e-16」。**

**→ 这个测试是：自己算 IBM，自己再逆回去，比对自己算的矩阵。**

**→ 它证明了**算术没错**，但**完全没碰到「写进文件时的字节顺序」**。**

**⚠️ 这是本系列最重要的方法论教训之一：**

> **验证必须用**独立的读取者**，不能用自己写的那一半去验另一半。**
>
> **正确的验收应该是：写完之后，用 glTF 规范的位置（12/13/14）**读回来**，
> 检查它是否等于 `-R^T·t`。**
>
> **那正是这次第 6 步做的事 —— 一次就抓到了。**

## 十、这次诊断的关键转折

| 步 | 尝试 | 结果 | 意义 |
| --- | --- | --- | --- |
| 1 | 查 bounds | **推翻既有记录** | 散开的是 COWF 不是 STATIC |
| 2 | 看长轴 | **假线索**（Z 最小）| 差点去改朝向 |
| 3 | **查骨骼** | **全部同一位置** | **找到真机制** |
| 4 | 查 glTF 节点 | 节点对的，IBM 全零 | 缩小到矩阵 |
| 5 | **查 3/7/11 槽** | **67/67 平移在这** | **证明转置两次** |

**→ 第 2 步是**陷阱**，第 3 步是**转折**。
**如果停在「Z 最小 → 转 90°」，就会去改一个**不存在的朝向问题**，
而真正的 bug（骨骼塌缩）还在。**

**⚠️ 教训：包围盒只能说明「形状怪」，说明不了「为什么怪」。
骨骼位置才是**结构**证据。**

**2. 包围盒正常不代表模型正确 —— 它只量顶点，不量矩阵/绑定。**

### 12.1 方法：改一份副本，量完再删

**不动真资产，三步：**
1. 复制 `boss001.gltf` / `.bin`，只改逆绑定矩阵的字节
2. 导入到 `/Game/Moxiang/Test/`（临时路径）
3. 量骨骼跨度，然后**删掉测试资产和副本**

### 12.2 第一次：只修槽位顺序

**补丁：把平移从 3/7/11 挪到 12/13/14。**
```
moved the translation on 67 of 67 matrices
verification: matrices with translation in slots 12/13/14: 67
```

**导入后量骨骼（✅ 实测）：**
```
BROKEN (original):  67 bones, span X=0.0     Y=0.0     Z=0.0     cm
SLOTS FIXED:        67 bones, span X=31351.3 Y=28949.8 Z=39738.4 cm
```

**→ 骨骼**有偏移了**（0 → 39738 cm），**槽位修复确实有效**。**
**→ 但跨度是 **397 米** —— 明显过大。**

### 12.3 🔴 修 bug 1 才让 bug 2 露出来：单位没缩放

**对比量级（✅ 实测）：**

| 项 | 值 | 量级 |
| --- | --- | --- |
| glTF **节点**平移（`Bip01`）| `[-0.00145, -3.49e-10, -1.3319]` | **1.33 米** |
| IBM 平移（**未缩放**）| `(32.15, -129.25, 0.145)` | **129** |
| IBM 平移（**×0.01 后**）| `(0.3215, -1.2925, 0.0015)` | **1.29 米** |

**→ 只有缩放后才和节点平移**同量级**。**

**根因：`cp()` 把顶点从厘米转成米（`* 0.01`），
但 `invert()` 用的是 `parse_mod` 读出的**厘米**矩阵。两者单位不一致。**

**→ 39738 cm ÷ 100 = **397.4 cm ≈ 3.97 米** —— 正好是 Boss 的合理身高
（原 bounds 是 2.97 × 2.72 × 2.08 米）。**

### 12.4 两个 bug 的完整结论

| # | 缺陷 | 现象 | 修复 |
| --- | --- | --- | --- |
| **1** | `invert()` 已是列主序，`build()` 又转置 | 平移跑到 3/7/11，骨骼塌缩到原点 | `column_major = inverse` |
| **2** | IBM 用厘米，顶点用米 | 修了 #1 后骨骼跨度 397 米 | 平移部分 `× 0.01` |

**→ **必须两个都修**。只修 #1 会得到「能蒙皮但放大 100 倍」的模型。**

**⚠️ 这是**顺序调试**的典型：第一个修复把第二个 bug 从「被掩盖」变成「显形」。**
