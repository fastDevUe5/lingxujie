# UE5 Python API 体量实测与掌握路径

> **目标里说「对标 11,675 个 API 类」。这个数字我之前一直引用但**没验证过**。
> 这篇是实测，以及基于实测的「该学什么」的判断。**

---

## 一、实测数据（2026-11-26）

**用 `Tools/inventory_python_api.py` 直接数 `dir(unreal)`：**

| 项 | 数量 |
| --- | --- |
| 模块属性总数 | **11,509** |
| **其中类** | **11,459** |
| 可调用但不是类（函数） | 49 |
| 其他值 | 1 |
| **所有类的可调用成员合计** | **330,365** |

**⚠️ 文档里写的 11,675 与实测 11,459 差 **216**（1.8%）。**
**差异可能来自 UE 版本或统计口径（是否算内部类）。**
**结论：11,675 这个数字方向对，但不精确。以后引用实测值。**
**（这是第四次「引用了没验证的数字」，见 gotcha #80 的三问法。）**

## 二、11,459 个类怎么分布（按首词粗分）

**我的首词匹配只覆盖了 15 个前缀，所以 9,754 个落进「other」—— 这个统计本身**不完整**。**
**但可见部分有参考价值：**

| 首词 | 类数 | 说明 |
| --- | --- | --- |
| **other** | **9,754** | 我的前缀表覆盖不到（**统计缺陷**）|
| **Material** | **515** | **材质相关类最多** |
| Data | 123 | 数据表 / 资产 |
| Audio | 112 | 音频 |
| Sound | 103 | 声音 |
| Editor | 92 | 编辑器 |
| Input | 89 | 输入 |
| Physics | 70 | 物理 |
| Texture | 66 | 贴图 |
| Game | 60 | Gameplay |
| Widget | 56 | UI |
| Actor | 43 | Actor |
| Slate | 43 | Slate UI |
| Mesh | 41 | 网格 |

**为什么 Material 有 515 个？**
**因为材质表达式（MaterialExpression）每种节点就是一个类。**
**我们搭三平面时用了 8 种，而引擎有 515 种。**

## 三、330,365 这个数字才是关键

**11,459 个类平均每类 28.8 个方法。**
**但分布极不均匀：**

| 类 | 方法数 |
| --- | --- |
| **`MathLibrary`** | **728** |
| `SkeletalMeshComponent` 及其 7 个派生类 | **各 471** |
| （其余平均） | 28.8 |

**`SkeletalMeshComponent` 有 7 个派生类，每个都继承 471 个方法 ——
这意味着「类数」严重高估了「独特知识量」。**

**同一批方法在多个类里重复出现。**

## 四、所以「精通 11,459 个类」是什么意思

### 4.1 不可能，也不必要

| 算法 | 结果 |
| --- | --- |
| 330,365 个方法 / 每天 100 个 | **9 年** |
| 11,459 个类 / 每天 10 个 | **3.1 年** |
| **去掉继承重复，独立表面可能只有 3–5 万** | 半年到一年 |

**而且**绝大部分类和本项目无关**（Android、IOS、Switch、HoloLens 平台类、
编辑器工具类、实验性插件类）。**

### 4.2 本项目真正会碰到的类（估算）

**按实际工作推导：**

| 领域 | 大概类数 |
| --- | --- |
| Actor / Component / Pawn | ~200 |
| 资产与导入 | ~100 |
| 材质 | ~120（515 里常用的）|
| 音频 | ~60 |
| 物理/碰撞 | ~50 |
| 输入 | ~40 |
| 动画 | ~80 |
| UI | ~60 |
| 渲染/后处理 | ~80 |
| 数学/容器 | ~80 |
| **合计** | **~870 个类** |

**约 870 / 11,459 = 7.6%。**

**这才是「对本项目精通 UE5」的真实分母。**

## 五、我已经掌握了多少（诚实量化）

**用「实际调用过的类」来数 —— 这是我唯一诚实的标准：**

| 来源 | 类数 |
| --- | --- |
| `Tools/` 下 45 个脚本里 import 并调用过的 | ~60 |
| 文档里逐行读过的（13 个工具集 + 核心类） | ~120 |
| **实际调用过** | **~60** |
| **读过源码并写进文档** | **~120** |
| **两项并集** | **~150** |

**150 / 11,459 = **1.3%**
**150 / 870（本项目相关）= **17.2%****

### 5.1 但按「使用频次加权」完全不同

**罗特卡法则（幂律）：前 20% 的类承担 80% 的使用。**

**本项目最常用的 20 个类：**

| 类 | 用在哪 |
| --- | --- |
| `EditorAssetLibrary` | 所有脚本 |
| `StaticMeshComponent` | 摆几何 |
| `ActorSubsystem` | 所有关卡操作 |
| `LevelEditorSubsystem` | 保存/重建 |
| `MaterialEditingLibrary` | 三平面 |
| `AssetTools` | 导入 |
| `UnrealEditorSubsystem` | 相机 |
| `GameplayStatics` | 播放声音 |
| `StaticMeshEditorSubsystem` | 合并 |
| `EditorActorSubsystem` | 生成/销毁 |
| … | … |

**这 20 个我**全部实际用过并验证过**。**
**它们覆盖了本项目 80%+ 的编辑期操作。**

## 七、按这个实测，接下来该学什么

**不该学"更多类"，该学"本项目还没碰过的领域里最高频的类"：**

| 顺位 | 领域 | 为什么 |
| --- | --- | --- |
| **1** | **动画（SkeletalMesh + AnimInstance）** | **471 个方法的大类，且 .mod 转换是硬阻塞** |
| 2 | UMG（56 个 Widget 类） | 古风 UI 做不出来 |
| 3 | 后处理（350 字段，已读但没调过） | 观感 |
| 4 | 网络（P0 不需要） | 最后 |

**而不是去数剩下的 11,000 个类。**
