### 2.4 墨香格式（**完全解开**）

**.mod 布局：**
```
FILE_BASE_OBJECT_HEADER  324  (dwIndex 4 + NODE_TM 184 + children 4 + parent 4 + name 128)
FILE_MESH_HEADER          48  (vertexNum@+4, extVertexNum@+12, texVertexNum@+16, faceGroupNum@+24)
positions                 12 × V
uvs                        8 × T
extIndices                 4 × E
faceGroups                FILE_FACE_GROUP_HEADER 28 字节 + 2×faces×3 + 8×lightUV1 + 8×lightUV2
FILE_PHYSIQUE_HEADER      12
PHYSIQUE_VERTEX × n        5  (bBonesNum u8 + boneStartIndex u32)   ← 影响数 1–3 可变
BONE × bones              44  (index u32 + weight f32@+4 + 3×VECTOR3)
normals                   12 × V  ← **条件性！**（见下）
```

**容器：** 8 字节块头（`u32 marker` + `u32 size`），marker
`0x00F00000`=MATERIAL / `0xF5000000`=BONE / `0xF4000000`=MESH。

**.anm 布局：** 块头 8 字节 + `FILE_MOTION_OBJECT_HEADER`（**152 字节**），
键序 **POS(20) → ROT(24) → SCALE(36)**。
**帧率 = 30 fps**（160 ticks/帧，4800 ticks/秒）。

## 八、第 37–38 轮的补充（材质结构）

### 8.1 材质槽：1 → 40

**`boss001.mod` 的 40 个 MATERIAL 块，原来只导入 1 个槽（全身一个表面）。**

**原因是面组的材质索引被合并了：**
```
MESH @83800: faceGroups=6
   group 0: mtl=39  index=5
   group 1: mtl=38  index=4
   ...
```

**修法：每个面组一个 primitive（glTF 允许多 primitive 共享顶点属性，只换索引缓冲）。**

**结果：**
```
primitives: 17 → 40
materials:  0  → 40
UE 槽数:    1  → 40
```

**回归：7 个模型包围盒**完全不变**，primitive 数各自增加。**

### 8.2 40 个材质只有 1 张贴图

**逐块打印 40 个 MATERIAL 块，全部引用 `boss_mob01.tga`，`dwIndex` 全是 0。**

**材质块字段布局（前 64 字节）：**
```
00000000  <- dwIndex
e8eff500  <- 颜色 1 = (232, 239, 245)
e8eff500  <- 颜色 2
ffffff00  <- 颜色 3 = 白
cccccc3d  <- float 0.100
偏移 156  <- 贴图名
```

**40 个块只有 2 种颜色：37 个 `(232,239,245)`、3 个纯白。**

### 8.3 所以「所有槽一个外观」是源数据的性质

**不是管道简化。原游戏就是「一张图集 + 近乎统一的材质参数」，视觉差异全在 UV 区域。**

### 8.4 两个新坑

| 编号 | 内容 |
| --- | --- |
| **#105** | 面组材质索引被合并 —— 40 个材质变 1 个槽 |
| **#106** | 「改了但画面没变」：先分清是没生效还是没有可见差异 |

**#106 的方法：把被改的量**读出来**看数值，不要靠画面判断 —— 画面是间接证据。**
