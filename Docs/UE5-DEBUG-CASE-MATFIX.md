## 三、🔴 同一次改动，三种测法三个答案

| 测量范围 | 差异像素 | 判读 |
| --- | --- | --- |
| **全画面** 1180×688 | **0.99%** | 「几乎相同」← **数字正确，结论误导** |
| 我猜的区域 (480-650, 370-480) | 8.8% | 看不清 |
| **生物实际区域** (480-600, 340-430) | **24.0%** | **清晰** |

### 3.1 为什么全画面只有 0.99%

**那个生物在画面里只占约 8000 像素 / 811,840 像素 = 1%。**
**→ 全画面像素差**数学上是对的**，但作为「改动有没有生效」的证据，**它几乎没用**。**

**⚠️ 我的 `diff_captures.py` 判据阈值（2% / 50%）是给**全场景变化**定的
（比如 `vis` 改动是 16.7%）。对**小物体**，这个阈值永远判「几乎相同」。**

### 3.2 为什么中间那个区域也只有 8.8%

**我按印象框了 (480-650, 370-480)，那个框**大部分是地面**。
→ 生物只占框的一部分，差异被地面稀释。**

**→ 区域选错，答案就错。**

### 3.3 正确的区域给出 24%

```
region: (480,340) to (600,430), 10800 pixels
changed: 2593 (24.0%)
mean colour before: (151.0, 134.8, 97.1)
mean colour after:  (148.0, 126.1, 87.1)
channel shift:      (-3.0, -8.6, -10.0)
```

**→ **24% 的像素变了**，G 和 B 各降 9-10 —— 符合「在灰色上叠了红棕贴图」。**

**→ 数字终于和画面对上了。**

## 四、🔴 最重要的教训：**先看图，再选区域**

**我犯的顺序错：先算全画面 → 得到 0.99% → 怀疑「是不是没生效」→ 才去看图。**

**正确顺序应该是：**
```
1. 先看两张图（或 cropped 对比）
2. 找到变化在哪
3. 按变化的位置框区域
4. 再算数字
```

**→ 数字是**验证**，不是**发现**。**
**→ 用数字去找变化，会在小物体上失败。**

**⚠️ 这和本系列反复出现的「结论与观察矛盾时先信观察」是同一条，
但这次是反过来的方向：**我让数字先说话，而它说错了。****

## 五、还原遇到的坑

**第一次还原用 `component.clear_material_override(slot)` —— **这个 API 不存在**。**

**错误处理还写错了：`log_error` 那一行本身被当成错误消息打了出来，掩盖了真正的原因。**

**修法：**直接赋回默认材质**，结果状态相同：**
```python
default = unreal.load_asset("/Engine/EngineMaterials/WorldGridMaterial.WorldGridMaterial")
component.set_material(0, default)
```

**✅ 还原验证：**
```
REV: current: 'M_Boss_Mob01'
REV: after:   'WorldGridMaterial'
REV: restored: True
复查: NOW: 'WorldGridMaterial'
```

**→ 这是**第二次**在这条任务线里因为猜 API 名字而失败
（第一次是 `get_num_lod_levels` → 实际 `get_num_lods`）。**
