## 一、修掉的三个 bug

### 1.1 只导出第一个网格块（gotcha #84）

**`198_bobu.mod` 有 3 个 MESH 块（164 / 632 / 37 顶点），导出器只取 `meshes[0]`。**

**症状：包围盒 34.3 × 44.0 × 39.5 cm。**

**修法：每块一个 glTF primitive，共用同一个 skin。**

### 1.2 顶点是世界坐标（gotcha #85）

**顶点都在 (2300, 2500, -100) cm —— 模型在原地图里的世界位置。**

**症状：actor 位置对但几何在画面外。**

**修法：减去顶点中心。**

### 1.3 🔴 对象的 `NODE_TM` 矩阵没应用到顶点

**这是「趴着」的根因。**

**每个对象的基类头里有 `NODE_TM`（184 字节），含位置 / 旋转轴角 / 缩放 / **两个准备好的矩阵**。**

**实测 `198_bobu.mod` 的三个网格：**

| 网格 | fRotAng | fPos | fScale | mat4 平移 |
| --- | --- | --- | --- | --- |
| `N012-1` | **2.0071 弧度（≈115°）** | (2278.8, -8.3, 2438.3) | **0.7314** | (2278.8, -8.3, 2438.3) |
| `N012` | 0 | (0, 112.7, 20.5) | 1.0 | (0, 112.7, 20.5) |
| `N012-2` | 3.1661 弧度 | (23.7, 0.1, 9.3) | 1.0 | (23.7, 0.1, 9.3) |

**所以各部件靠 `NODE_TM` 摆到各自位置 —— 有旋转 115° 的，有抬高 112.7cm 的。**

**不应用这个变换，部件就散落、模型就趴着。**

**mat4 是**行向量约定**，平移在最后一行：**
```
[-0.3091  0.0000  -0.6629  0.0000]
[ 0.0000  0.7314   0.0000  0.0000]
[ 0.6629 -0.0000  -0.3091  0.0000]
[2278.78  -8.35  2438.33  1.0000]
```

**变换公式（行向量 × 矩阵）：**
```python
x' = x*m[0] + y*m[4] + z*m[8]  + m[12]
y' = x*m[1] + y*m[5] + z*m[9]  + m[13]
z' = x*m[2] + y*m[6] + z*m[10] + m[14]
```

**修后：**
```
primitive 0: extent=(0.56, 0.58, 0.64) m
primitive 1: extent=(1.26, 1.10, 1.56) m   ← 主体
primitive 2: extent=(1.16, 1.36, 0.43) m
```

**各部分对齐了、尺寸合理了（1–1.5m）。**

## 七、朝向问题：已关闭（第 20 轮）

### 7.1 「最高轴」不是有效的朝向判据

**原计划：用两种映射各导一次，保留让 Z 最高的那个。**

**实测七个模型（同一套映射，已应用 mat4）：**

| 文件 | 顶点 | X / Y / Z (cm) | 最高轴 |
| --- | --- | --- | --- |
| `198_bobu` | 632 | 126 / 156 / 110 | Y |
| `w25260` | 32 | 10 / 20 / 23 | Z |
| `216` | 517 | 59 / 134 / 71 | Y |
| `20_eagle_01` | 226 | 84 / 177 / 139 | Y |
| `108_bird` | 146 | 143 / 111 / 144 | Z |
| `19240` | 348 | 174 / 98 / 133 | X |
| `choco` | 190 | 186 / 149 / 40 | X |

**分布：`{'Y': 3, 'Z': 2, 'X': 2}` —— 没有任何轴占主导。**

**原因：**
> **「最高」只对直立人形等于「高度」。
> 对鸟是**翼展**，对四足兽是**体长**，对扁平道具是**宽度**。**

**所以这个判据本身是错的，不是映射错了。**

### 7.2 正确的判据：源格式自己的约定

**客户端是 **Z 朝上**：**

| 证据 | 出处 |
| --- | --- |
| `.hfl` 高度场把高程存为 **Z** | `FORMAT-REFERENCE.md` 第二节 |
| `.map` 物件摆放 `(x y z)`，**z 是高程** | 同上，第五节 |
| `HFIELD_DESC` 的 `left/top/right/bottom` 是 XY 平面 | 同上 |

**而我的映射 `(x, z, -y)` 让 **glTF 的 Y = 源的 Z** —— 这正是 Z-up → Y-up 的标准转换。**

**→ 映射正确，不需要改。**

### 7.3 那 `198_bobu` 为什么看着矮？

**它的尺寸是 126 × **156** × 110 cm —— **体长大于身高**。**

**它就是一只**矮胖生物**，不是误差。**

**对照 `20_eagle_01` 的 84 × **177** × 139：Y 是**翼展**，鸟张开翅膀本来就比身高宽。**

### 7.4 这一轮的教训

> **选了一个判据，它对该模型不成立，却以为是管道错了。**
>
> **判据要能被反驳** —— 「最高轴」在第一个模型上就给了一个可疑的答案，
> 但我先改代码，后验证判据。顺序反了。

**这和前几轮的错误同类：先有结论，后者证。**
