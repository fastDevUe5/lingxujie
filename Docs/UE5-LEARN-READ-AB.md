# UE5 学习 · 补读（三）：用标准流程重做 Nanite 对比 —— 46.37%

> **这一篇把上一轮的教训变成了流程：先冻结动画、先量噪声底，再做 A/B。
> 结果 Nanite 的差异是 **46.37%**，底噪只有 **0.62%**。**
>
> **日期：2026-11-27 · UE 5.8.4**

---

## 一、标准流程（上一轮教训的产物）

```
1. 找出画面里「会动」的东西（体积云 = 主要噪声源）
2. 冻结它（r.VolumetricCloud 0）
3. 什么都不改，连拍两张 → 量噪声底
4. 只改一个变量，再拍 → 量差异
5. 差异 / 底噪 才算有意义
6. 还原所有 CVar
```

**→ 上一轮就是漏了 1–3，才把云的动画当成 Lumen 的效果。**

## 二、这次执行

### 2.1 主关卡真的有云（✅ 实测）

```
volumetric cloud actors in the level: 1
```

**→ 主关卡自己就有体积云，**之前做 Lumen 对比时如果在这里做，也会踩同一个坑。****

### 2.2 冻结 + 量底噪

```
A1 = Nanite 开，云关
A2 = Nanite 开，云关（什么都不改，再拍一张）
```

| 比较 | 结果 |
| --- | --- |
| **噪声底 A1 vs A2** | **0.62%** |

**→ 底噪 0.62%，比之前的 5.4–7.7% 低了约 10 倍。**
**→ 证明「关云」这一步确实把主要噪声源去掉了。**

### 2.3 只改 Nanite

```
B1 = Nanite 关，云关
```

| 比较 | 结果 | 判定 |
| --- | --- | --- |
| **噪声底** | **0.62%** | — |
| **Nanite 开关** | **46.37%** | ✅ **75 倍于底噪，信号确凿** |

## 三、🎯 引擎给出了**铁证**

**关掉 Nanite 的瞬间，日志出现：**
```
[VSM]非Nanite标记工作队列溢出。性能可能会受到影响。
当许多非Nanite网格体覆盖阴影贴图的大面积时，就会发生这种情况。
```

**→ 正是 `nanite.md` 里说的：Nanite 网格走 **Virtual Shadow Map 的 Nanite 路径**，
关掉 Nanite 后它们全部变成「非 Nanite 网格」，
→ **VSM 的非 Nanite 标记工作队列溢出**。**

**→ 这是一个**真实的性能事件**，不是推测。**

## 五、这一篇的三条教训

**1. 🎯 标准流程有效，而且成本很低。**
关云 + 多拍一张，换来的是「0.62% vs 46.37%」这种能下结论的数字。

**2. 🔴 主关卡自己也有一条体积云。**
以后在主关卡做任何像素对比，都得先关它。

**3. 🎯 引擎警告比像素差异更直接。**
46.37% 说明「画面变了」，VSM 溢出警告说明「**为什么**会变、以及这是性能问题」。

**→ 排障时应该两条一起看：像素告诉你**发生了什么**，日志告诉你**为什么**。**
